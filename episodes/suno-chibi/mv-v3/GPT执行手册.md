# 给 GPT 的执行手册：赤壁借风 mv-v3

你负责在用户本机的 ComfyUI 上用 MiniMax H3 生成 v3 素材并重剪。导演方案已定，**你只执行，不改创作**。

先读：`导演修改方案.md`（为什么这么拍）、`补图提示词.md`（参考图）、`plan.json`（唯一权威：素材、提示词、时间线）。

## 绝对不要做

- 不改 UNet、LoRA、LoRA 强度、步数、采样器、分辨率、帧率（脚本里已写死）
- 不换歌、不改词、不改 vocals.wav / song.wav
- 不动 `mv-v2/` 目录和 v2 成片
- 不把 `records/task.json` 拷回来恢复任务
- 不自己改 plan.json 的镜头设计；需要改时先问用户
- 不把一条素材连续切成三段放（重复镜头）

## 步骤

所有命令都在仓库根目录运行；Windows 用 `python`，不用 `python3`。

1. **补图**：按 `补图提示词.md` 生成 11 张图，逐张过 "收图检查"，存进 `episodes/suno-chibi/mv-v3/refs/`。
2. **检查**：`python scripts/v3.py check`，"缺参考图" 必须是 "无"。
3. **准备**：`python scripts/v3.py prepare`，切好每条的 drive.wav / mix.wav，把 A03、END02B 从 v2 拷过来。不提交任何任务。
4. **测一条**：`python scripts/v3.py run A01`。生成后用播放器**带声音**看 `mv-v3/clips/A01/video.mp4`：前 0.25 秒应该是闭嘴的前导；口型要跟上；必须是仰拍。把结果发给用户确认，用户同意再批量。
5. **批量**：`python scripts/v3.py run`，串行提交，已有 video.mp4 的跳过。本机 GPU 一条一条排队，时间长就后台运行。
6. **逐条验收**（下面的表），不合格的重抽：`python scripts/v3.py run B01 --retake`（旧 take 自动存进 takes/，换种子）。
7. **重剪**：`python scripts/v3.py render`，输出 `episodes/suno-chibi/赤壁借风-周瑜对诸葛亮-成片-v3.mp4` 和 `mv-v3/成片总览-v3.jpg`。
8. **交付**：把 v3 成片发给用户，附上每条素材用了第几个 take、哪些用了备用方案。

## 逐条验收标准

通用（每条都查）：
- 人物脸、服装和参考图一致；周瑜无胡子，诸葛亮有胡子
- 麦克风在右手、不挡嘴；羽扇在诸葛亮左手、唱歌时不过嘴；羽扇没有变形成折扇
- 镜头内没有跳切、没有多出来的人进圈、没有文字水印
- 机位和景别符合方案（仰拍就要真仰拍，大特写就要真的近）

唱歌素材（OPEN3、A01、A02、A04、ZG_YEAH、B01–B04）：
- 只有唱的人张嘴，另一个人闭嘴
- 开头 0.25 秒闭嘴，唱完停止动嘴
- 口型跟得上原歌（放声音看，抽帧不算数）
- 歌词里写的动作要出现在对应的字上（例：B01 "借我的风" 那一扇和周瑜后仰）
- A02 只用前 1.25 秒、B02 只用前 1.8 秒：这两条的动作必须在前半句完成

反应素材（ZG_R1、ZG_R2、RING、FAN、ZY_REACT、ZY_FINAL、CHAMP）：
- 全程没有人在说话或动嘴（笑可以）
- 表情变化要看得出来（挑眉、咬牙、苦笑）
- ZY_REACT：前 1.1 秒是挑衅勾手，第 92–110 帧是咬牙；不对就重抽
- CHAMP / RING：台上两个人都要清楚可见

## 重抽规则

- 一条最多抽 3 次；第 3 次还不行，用 `导演修改方案.md` 的 "失败时的备用方案"，并告诉用户
- 用备用的 v2 素材时：把 v2 的 video.mp4 拷到 `mv-v3/clips/<素材名>/video.mp4`，再按备用说明改 plan.json 里对应 timeline 的 `in_frame`，改动要告诉用户
- 小问题能剪掉的（比如最后几帧穿帮）不用重抽，告诉用户

## 汇报格式

每条素材一行：`素材 | 第几个 take | 通过/不通过 | 问题`。最后附成片路径和总览图。
